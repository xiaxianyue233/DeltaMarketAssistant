# 三角洲商城助手

这是一个仅在 Windows 前台工作的外部图像识别工具。它不读取游戏内存、不注入游戏进程，也不联网上传截图。

当前源码基线为 **v1.20.0**，Git 版本管理从此版本开始。开发资料：

- [开发说明与架构](docs/DEVELOPMENT.md)
- [开发过程](docs/DEVELOPMENT-HISTORY.md)

在 Windows 与 .NET 8 SDK 环境运行 `./tools/Build.ps1` 可构建并执行仓库内 21 项回归；加 `-Publish` 同时生成单文件程序。完整个人截图与配置不包含在源码归档中。

## 首次使用

1. 以 16:9 分辨率打开游戏商城收藏列表，并保持游戏为无边框或窗口化前台窗口。
2. 启动 `DeltaMarketAssistant.exe`，选择游戏窗口并点击“开始校准”。
3. 在一级按钮显示“公示中”的主界面按 `F10`，依次框选第一件收藏、一级按钮、刷新按钮和按钮上方的整行倒计时。倒计时包含“分、秒”，左右留空适应文字长度变化，不包含价格按钮。在样本确认窗口核对截图中的实际分秒，可录入本机数字形状，也可以不录入。
4. 回到游戏，等一级按钮出现价格后手动打开二层购买弹窗；不要点击最终价格，按 `F10` 后依次框选“外观购买”标题区、绿色确认价格区域及其上方整行倒计时，并核对数字样本。
5. 先选择“仅识别（不点击）”及“倒计时驱动”，用 `F8` 启动，核对日志中的“本地倒计时”与屏幕一致；手动打开二层也可以查看该区域的识别结果。未匹配或跳变时先修正校准，不能直接启用购买。
6. 需要实际运行时选择“自动购买（会点击）”，再按 `F8` 或点击开始按钮。

`F8` 默认为开始/暂停，`Ctrl+Shift+F9` 为紧急停止；已有自定义设置继续保留。点击热键输入框并按下所需组合，再点击“保存并应用”。支持 Ctrl、Alt、Shift 搭配字母、数字或功能键；校准键和系统保留键不能设置。注册冲突时会尝试恢复原来的热键组。

时间参数的有效修改会在停止输入约 500ms 后自动保存；无效或越界输入保留在界面并提示，不会悄悄改回。点击“保存并应用”会暂停当前流程，下一次开始使用完整的新参数。当前运行使用独立配置快照，不会在一轮购买中途切换节奏。每个时间控件与后端共用同一份定义和范围。

## v1.20 已开放商品限时补购

- 新打开的二层如果显示“剩余：2天23小时”等挂牌时间、没有可信的开抢倒计时，且原购买窗口与绿色价格按钮连续两帧验证通过，不再直接 Esc，而是限时补购 2000ms。挂牌时间不能证明仍有库存，程序不判断实际成交概率。
- 补购沿用界面的“点击间隔”，不等待固定冲刺延迟，也不叠加普通冲刺时长、额外续点或结束后续点；两秒从补购验证通过时起算，不因重复读数、重试提示或按钮暂时变灰而延长。暂时变灰时不点击，恢复绿色可在原两秒期限内继续。
- 一旦出现已知结果、成功特征、一级商城或原二层消失，立即停止补购，恢复画面也不会重开本轮。捕捉失败、前台丢失与紧急停止仍会暂停；“仅识别”模式不发送输入。
- 两秒结束仍未明确返回时，直接进入受保护的返回流程，不再额外等待正常结果超时：验证后最多单次 Esc，已在一级则不按 Esc，确认一级稳定后刷新一次并重选队首。成功页继续走跳过及单次空格流程。
- 本功能仅处理本轮打开且已验证的二层；未知文字、仅有绿色区域或正常冲刺结束后不会新增补购窗口。正常倒计时和固定延迟流程保留。无需重新校准或修改现有参数，补购两秒是本版独立的固定上限。

## v1.19 冲刺交接连续点击

- 倒计时进入“提前开始”阶段后锁定本轮点击窗口，直到“开放时点 + 结束后续点”才结束。交接时数字短暂无法匹配或从最后一秒切换到零秒，不会重新等待；实际画面捕捉失败仍暂停，不会盲点。
- 没有可信开放时点的商品不会因为这个锁定机制开始点击；固定延迟模式和结果/成功/返回界面的安全停止仍优先。

## v1.18 挂牌页面返回（历史行为，已由 v1.20 替换）

- 新开的二层如果显示“剩余：2天23小时”等挂牌时间，且本轮尚未发送购买点击、没有可信的开抢时点，连续两帧匹配本地“时钟＋剩余”模板后进入返回流程。这只识别时间类型，不证明商品已售出，也不会用购买点击试探。
- 返回前仍须连续验证本轮原购买窗口标题与底部返回提示，发送前再次检查；最多单次 Esc。确认到达收藏一级后刷新一次并重选队首。已经回到一级时不再 Esc，捕捉失败、窗口切走或未知页面仍暂停。
- 本分支适用于倒计时和固定延迟两种模式；已经开始的冲刺不会因为挂牌时间出现而提前截断，原有结果判定、续点上限和安全停止继续生效。原有校准与时间设置保留，不新增参数。

## 倒计时模式（v1.17 起）

- 从 v1.17 之前的版本升级后默认使用“倒计时驱动”。旧配置保留，但必须重新校准补充两个倒计时区域；也可手动选择“固定延迟”沿用旧流程。不会把一般识别失败降级成固定延迟购买；v1.20 的挂牌补购必须另行验证挂牌时间及绿色购买按钮。
- “提前开始(ms)”默认 3000，“结束后续点(ms)”默认 2000。二层验证时剩余约 5 秒就等待约 2 秒，剩余约 3 秒或 1 秒时直接开始；结束时间始终锚定当前商品，不因为开窗或重复读到相同数字而延后。此模式不使用固定延迟、冲刺时长和额外续点，界面只显示对应模式参数。
- 本地像素分割、数字/分/秒/锁图标模板匹配，模板来自已有截图、Windows 本机字体和校准时用户确认的数字样本。只接受完整的分钟秒数结构，不接受价格、天小时、未知首位数字或有歧义的匹配。
- 每约 100ms 尝试读取倒计时，连续两帧确认；对当前商品使用单调时间估算开放时点。重复数字不重置时钟；刷新和重选队首会丢弃旧商品时点。普通冲刺开始前，600ms 没有可信更新会禁止新的购买点击，持续无法识别或发生跳变时暂停。v1.19 起，已开始的普通冲刺锁定结束时点，数字失配不重启计时；画面与输入安全检查仍持续执行。
- 新商品只有“0秒”而没有近期正数倒计时，无法判断其何时开放，不猜测时点、不购买。重新校准不会凭空补齐所有未知数字；可在显示未识别数字时抓取校准画面并录入该样本。学习到的归一化数字形状保存在 `config.json`。
- 屏幕倒计时有整数取整、刷新延迟和识别误差，估计时点不是服务器时钟，无法保证毫秒级同步。应用不读取游戏内存、游戏文件或网络请求；仍需取得窗口标题/位置并使用外部模拟输入，因此不能保证不会被游戏限制或标记。

## 运行约束

- 游戏必须保持前台、不能最小化，也不能被其他窗口遮挡。
- 客户区必须保持 16:9；可在 1080p、1440p、4K 等尺寸之间缩放。
- 自动购买模式在一级商城等待开放时默认每 1000 毫秒点击一次刷新并重新选择队首；可在控制窗修改刷新间隔，一级按钮开放后会立即停止定时刷新并进入购买流程。
- 备用的“固定延迟”模式不读倒计时：一级价格按钮开放后先打开二层，每轮从二层验证时独立计时，默认延迟 4000ms 后冲刺。固定模式默认冲刺 3000ms，再额外续点 2000ms；冲刺时长最小 500ms、上限为配置整数类型 2147483647ms，额外续点为 0-2000ms。
- 两种模式都会在结果出现、二层消失或安全条件失效时提前停止，不会为了凑满时间继续点击。
- 一级锚点和校准的刷新图标同时匹配时立即锁定停止输入；之后连续稳定验证返回状态。确认区域消失且一级界面稳定也是返回判据，不再只凭背景纹理阻止退出。
- 每次识别后只发送一个完整点击，默认间隔 100ms，界面可调整到 100-1000ms；每次提交要求本轮原购买窗口标题仍匹配且按钮为绿色，按钮暂时变灰时等待，不点击“查看结果”。间隔以实际发送结束时间重新计算，卡顿后不补发。旧配置的 `ConfirmClicksPerPacket` 不再用于购买连点。
- 二层弹窗退出后才视为确认完成；每轮完成或异常恢复后只点击一次刷新，再重新选择队首。
- 返回流程保留 100 毫秒输入排空，但不重复排空；默认返回稳定等待降至 75 毫秒，并要求主商城连续稳定 3 帧后才允许刷新。刷新后默认等待 150 毫秒，再验证队首画面连续两帧稳定才重选；加载较慢时继续等待，最多 1500 毫秒，不盲点。返回稳定和刷新等待都可在界面修改。
- 重选后立即检测下一件，不再额外等待一个定时刷新周期。流程仍是串行处理；前件冲刺或等待结果期间可能错过 5-10 秒后开放的下一件，缩短返回耗时不代表保证赶上所有商品。
- 使用内嵌的本地文字模板识别“队列已满”和“未抢购成功”，连续两帧确认后进入返回流程；roll 点数不参与匹配。结果检测首帧即停止输入，避免继续点击结果按钮。
- 返回前确认原购买窗口标题与底部 Esc 返回提示仍在，连续验证并临近发送时复核，只发送一次 Esc；若已经回到一级界面，不发送 Esc。返回稳定后刷新一次并重新选择队首。单次 Esc 后 5 秒仍未返回会暂停，不再连按。
- 使用成功截图中的“获得枪械外观”标题及“跳过”文字建立本地模板。任一成功特征出现时先停点，两者连续验证并在发送前复核后，只点击一次“跳过”，不点“应用外观”。
- 跳过后增加单次空格继续步骤：仅限本轮已发送跳过、原成功画面消失、未返回一级或原购买窗口，且新页面标题区域与底部提示区域都有细节并连续三帧稳定。至少等待 700ms，发送前重新捕捉并检查前台窗口，空格按下及抬起只发送一次。该判据是流程与画面稳定性启发式，不是对“获得外观/继续”文字的精确识别；手机拍摄图未用作精确像素模板。
- 跳过或空格后确认回到一级才刷新；若仍在本轮原购买窗口，则走受保护的单次 Esc 返回。最近一次跳过或空格操作后 5 秒仍无法验证返回会保存诊断并暂停，不反复跳过或按空格。捕捉失败、黑屏或窗口切走时不发送继续按键。
- 对不能识别的其它结果，默认停点后等待 15 秒（`ResultWaitTimeoutMs`），在原购买窗口仍可验证时单次 Esc 返回，不判断是否成交；无法确认的未知界面保存诊断帧并暂停。
- 停点后不会重开连点窗口。用户暂停、紧急停止、窗口失去前台及捕捉异常仍会停止输入。日志记录首次提交距二层验证的时间、实际间隔范围、结果判定、Esc 和刷新次数；操作系统接受点击不代表游戏服务器接受购买请求。
- 不读取价格，也不设价格或购买次数上限。
- 连续三次识别或流程异常后会自动暂停。异常帧和日志保存在 `%LocalAppData%\DeltaMarketAssistant`。
- 仅识别模式不会发送鼠标或 Esc；启动时已遗留的二层弹窗需先手动返回，自动结果退出只处理本轮打开且已验证的购买窗口。

## 构建与测试

```powershell
dotnet build .\DeltaMarketAssistant.sln
dotnet run --project .\tests\DeltaMarketAssistant.Tests\DeltaMarketAssistant.Tests.csproj
dotnet publish .\src\DeltaMarketAssistant\DeltaMarketAssistant.csproj -c Release -o .\publish
```

测试程序也可以读取实际截图：

```powershell
dotnet run --project .\tests\DeltaMarketAssistant.Tests\DeltaMarketAssistant.Tests.csproj -- --fixtures <主界面截图> <二层弹窗截图>
```

游戏可能限制自动化输入。使用前请自行确认相关规则和账号风险。
